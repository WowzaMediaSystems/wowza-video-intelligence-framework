Tiling Properties
Choose the tiling algorithm and tune the grid.
Fixed: uses one grid on every frame — the simplest and lightest option. Gated: uses two grids (a coarse one for big objects and a fine one for small objects) plus a full-frame look on every frame, for the best chance of catching both. It is the slowest, heaviest option, so choose it only when your scene mixes very large and very small objects.
(Gated only) How many top-to-bottom slices the coarse, big-object grid uses. Higher = more, smaller pieces (catches more, costs more processing); lower = fewer, bigger pieces (faster). Must be ≤ Max Slice Rows; set it equal to Max to use a single grid. Recommended: 3.
(Gated only) Same as Min Slice Rows, but left-to-right. Higher = more, narrower pieces (more detail, more processing); lower = fewer, wider pieces (faster). Must be ≤ Max Slice Cols. Recommended: 2.
How many top-to-bottom slices the grid uses (the fine, small-object grid in Gated mode). Higher = more, smaller pieces → better at small or distant objects but slower and more costly; lower = fewer, bigger pieces → faster but may miss small objects. Recommended: 6.
Same as Slice Rows, but left-to-right. Higher = more, narrower pieces (more detail, slower); lower = fewer, wider pieces (faster). Recommended: 4.
Filters out false detections that fill almost an entire piece (usually mistakes). Higher (toward 100) = more lenient, keeps more large detections but lets more false ones through; lower = stricter, removes more false detections but may drop real objects that genuinely fill a piece. 100 turns the filter off. Recommended: 100 (off); only lower it with Full Frame Detection on, so genuinely large objects are still caught by the full-frame pass.
Also analyzes the whole frame in one pass, on top of the grid pieces. This catches objects too big to fit inside a single piece (which the grid alone tends to miss or split into several wrong boxes). Costs a little extra processing per frame. Recommended: on when your scene also contains large objects.
Removes a large box when it actually contains at least this many smaller detections inside it (usually a mistake where one big box wraps a group of small objects). Lower (but above 0) = removes these more aggressively; higher = only removes the most obvious cases. 0 turns it off. Recommended: 0 (off); set to 3 if you see big boxes wrongly swallowing groups of small objects.

Synthetic (AI generated) Detection
Relay each source H.264 window to the NVIDIA Synthetic Video Detector NIM (over gRPC) for a per-window Real-vs-Fake verdict. Opt-in / bring-your-own endpoint; H.264-only; no re-encode.
SVD NIM as a gRPC host:port (not an http URL). Local sidecar: svd.docker:8001; NVCF hosted dev: grpc.nvcf.nvidia.com:443.
Force TLS for any endpoint reached over the network (pair it with the certificate paths under TLS Certificates below; TLS uses the system trust store otherwise). Auto-detect picks TLS when any certificate path below is set or the endpoint port is :443 (e.g. NVCF), and plaintext otherwise — plaintext is only appropriate for an in-network sidecar.
A self-hosted detector does not check API keys — anyone who can reach the endpoint can use it. If the endpoint is reachable from other machines, secure it with mutual TLS — see Securing the connection in the Synthetic Video Detector guide.
CA (or self-signed server) certificate for verifying the detector, as a file path readable by the Video Intelligence Service (e.g. /certs/ca-cert.pem). Needed whenever the server certificate is not from a public CA.
Client certificate for mutual TLS, as a file path readable by the Video Intelligence Service. Set together with Client Key Path.
Private key for the client certificate above, as a file path readable by the Video Intelligence Service.
